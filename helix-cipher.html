⚠ 本工具的定位与适用边界
本工具定位于「极端 / 应急情况下的自用备份方案」，不是经过认证的商用加密产品。
• 已有的可靠下限：外层 AES-256-GCM（NIST 标准，量子下约 2^128 仍安全）、 ChaCha20（RFC 7539）、格层（实测 2^273.9，抗量子）—— 这三层的强度对所有人都一样， 不依赖任何自研设计。
• 未经过第三方审计的部分：自研层（Feistel + Lai-Massey + Sponge）、Helix， 以及全部周边逻辑（KDF 参数、链式认证、填充、头部解析）。统计测试合格，但无人做过密码分析。
• 不是认证级 FIPS 140-3 L3：那需要把硬件模块送进 CMVP 实验室测评， 属载体问题，纯软件拿不到。
• 重要数据请优先使用成熟方案（如 VeraCrypt、硬件加密盘、 经认证的密码管理器）。本工具适合作为极端情况下的额外一层备份，而不是唯一依靠。
• 不建议依赖硬件密钥因子做长期存档： 凭据烧在硬件里导不出，硬件丢失或损毁 = 文件永久无法解开，且无法云备份。 在应急场景下，硬件本身也是新的失效点。

已登记状态：本文件已写入一枚哈希。若你更换了 Argon2 库、或改动了 ARGON2-BEGIN / END 之间的任何字符，校验会失败并禁用加解密 —— 这是设计意图。

被锁住怎么办：把 ARGON2_WHITELIST 改回空数组 [] 即可恢复使用； 然后重新复制页面显示的新哈希并写入。

哈希只计算 ARGON2-BEGIN 与 ARGON2-END 之间的内容， 所以你修改程序其它部分不会让哈希失效；但库本身被换会立刻被抓到。

加密文件 双密钥模式

离散对数层（DL）基于离散对数困难性，是经典攻击下的额外一族冗余。 但 Shor 算法可在量子计算机上多项式时间求解离散对数，故本层不具备抗量子性。
默认关闭：关闭时为五层（格层 → 自研层 → Helix → ChaCha20 → AES-GCM），全部对称结构、均抗量子；格层（LWE）本身即是抗量子的第七族。 仅在你需要最大经典冗余时勾选（代价：1MB 多约 30 秒）。
勾选后解密端会自动识别（标志写在文件头），无需手动记忆。
KDF 档位（影响解密难度与设备内存占用）
当前：桌面档。手机浏览器内存有限，1GiB 大概率直接崩溃或白屏；若加密卡死请改用移动档。
额外口令因子（可选 · 软件第三因子）
这是硬件密钥因子不可用时的替代方案：密钥由「密码 A + 密码 B + 额外口令」共同派生。 启用后解密必须提供同一个额外口令，丢失将无法恢复文件。
将自动生成两个 256 位随机密钥，并分别用「密钥文件保护口令」加密成两个 .hlk 文件。
两个密钥文件必须离网、分离保管，缺一不可。
v17.0 起：密钥文件与主文件同级，采用格层(LWE) + 自研层 + ChaCha20 + AES-256-GCM 四层加密（未含 Helix 与 DL：前者与 AES 同族，后者不抗量子，二者不增加实际安全性）。
保护口令用于解密密钥文件，必须自行牢记；丢失后密钥文件无法恢复。
因为它保护的是真正的 256 位主密钥（爆破它即可绕过主文件全部五层）， 强度要求与密码 A/B 一致：>=16 位且含大小写字母、数字、特殊字符。

手机上怎么启用？（点开）

唯一硬性前提：不能用 file:// 打开。 WebAuthn 需要域名作为 RP ID，本地文件没有主机名，必然失败。可选做法：

  • 把本 HTML 放到任意静态托管（GitHub Pages、Vercel、Netlify 等）用 https 打开；
  • 或在电脑起本地服务（python3 -m http.server），手机连同一局域网后访问 http://电脑IP:端口 —— 注意：局域网 http 不是安全上下文，仍需 https 才行， 所以手机端推荐直接托管到 https。

系统要求：iOS/iPadOS 18+ 的 Safari（iCloud 钥匙串）、 Android 的 Chrome（Google 密码管理器）均已支持 PRF。请在本机完成验证， 不要用扫码跨设备流程（该流程下 PRF 返回值可能不同）。

风险：Passkey 会随 iCloud / Google 账号同步 —— 好处是换机仍可解密，风险是一旦该 Passkey 被删除或账号丢失，文件将永久无法解开。 启用前请确认你能长期保留它。

安全说明（点击展开）

· v9.0 双层加密：内层自研 Helix-Cipher（32 轮、动态 ShiftRows、字节置换、轮常量、CTR 无填充），外层标准 AES-256-GCM 认证加密。
· 双 Argon2id（m=1GiB, t=12, p=1）派生主密钥，HKDF-SHA512 分离 master / mac / aes 三个密钥。
· v17.0 格式变更（0xB6）：新增第七族 —— 格层（LWE）：b = <a,s> + e mod q，基于格上的容错学习问题。LWE 抗量子（量子下无已知多项式算法，NIST 后量子标准 MLWE 即基于此族），也是与前六族都不同的困难性假设。同时离散对数层改为可选（默认关闭）—— 因 Shor 算法可解离散对数，关闭时全部层级均抗量子。关闭时为五层：格层 → 自研层 → Helix → ChaCha20 → AES-GCM；勾选 DL 后为六层。
· v16.0 格式变更（0xB5）：新增第六族 —— 离散对数层（DL）：mask = 低32字节(gk mod p)，p 为 RFC 3526 2048 位安全素数。它的困难性假设（离散对数）与前五族（SPN / ARX / Feistel / Lai-Massey / Sponge）完全不同，已知明文攻击者要跨块预测 mask 必须解离散对数。注：本层不具备抗量子性（Shor 可解离散对数），真正兜底抗量子的仍是 AES-256-GCM。
· v15.0 格式变更（0xB4）：修复自研层架构弱点——v14 三层共用同一轮函数（SHA-512⊕Keccak），两哈希同时被破则三层一起塌。本版改为三种不同构造：Feistel 用并联双哈希、Lai-Massey 用 Davies-Meyer 构造、Sponge 直接用 Keccak-f[1600] 原生置换（不经哈希）。另加层间白化破坏层间代数关系，轮数 12→20。旧版 .hlx / .hlk 需先用旧版解密后重新加密。
· v14.0 格式变更（0xB3）：新增自研层（最内层）—— Feistel + Lai-Massey + Sponge 三层复合，轮函数 = SHA-512 ⊕ Keccak-256（两个不同族哈希）。四种结构（SPN / ARX / Feistel / Lai-Massey / Sponge）互不相同的数学基础，即使 AES-256-GCM 与 ChaCha20 同时被攻破，自研层仍保护数据。代价：吞吐约 20 KB/s，1MB 文件约需 1-2 分钟，请耐心等待且不要关闭页面。旧版 .hlx / .hlk 需先用旧版解密后用本版重新加密。
· v13.0 格式变更（0xB2）：① 自研算法去 AES 化 —— S 盒改为在新域 GF(2^8)/0x12D 上构造（S=L(inv(x))⊕0x05，L 与常数均与 AES 不同），不再逐字节复制 AES 原表，质量仍为 δ=4 / NL=112；GF 不可约多项式由 0x11B 换为 0x12D。② 新增 ChaCha20 层（RFC 7539，ARX 结构，与 SPN 不同族），形成 ChaCha20 → Helix → AES-256-GCM 三层。旧版 .hlx / .hlk 需先用旧版解密后用本版重新加密。
· v12.1 格式变更（0xB1）：消除盐复用（Argon2 A/B、PBKDF2、HKDF 各用独立子盐，不再 salt XOR 0xA5）；文件封印纳入完整头部。旧版 .hlx / .hlk 需先用旧版解密后用本版重新加密。
· v12 修复/新增：Argon2 输出长度强制校验 + 库健康度自检（堵住静默降级）；解密端 KDF 参数按档位设上限（防伪造文件头导致手机内存耗尽）；解密改为分段流式（原为累积全部明文，峰值约 2 倍）；失败计数持久化（刷新不再清零）；加密端校验读取长度；块 IV 重复检测；回验标志校验；回报加密时间。
· v11 新增：Argon2 依赖源码完整性校验（白名单）；密钥派生改为单次 HKDF-Expand；GF 乘法表同样池化 + 无偏拒绝采样偏移；流式分块读写（不整体载入内存）；头部写入最低版本字节防降级。
· v10 新增：上电已知答案自检（KAT，向量取自 NIST / RFC 标准答案，非自洽）；Argon2id 后再串一层 PBKDF2-SHA512；逐块加密后解密回验做故障注入检测；SBOX 多副本随机池缓解缓存时序；密钥分片再藏进随机池；零化后逐字节验证。
· L3 映射项：运行时篡改自检（原生函数挂钩检测 / 脚本自校验 / 原型污染检测），异常即零化全部密钥分片。
· 密钥分片驻留：master 与 mac 密钥在内存中以 3 片 XOR 分片保存，仅在单次块运算内临时重组，用完立即 wipe，缩小完整密钥暴露窗口。
· 全文件链式认证：每块 tag 绑定上一块 tag，文件尾追加独立封印 MAC，任何重排 / 截断 / 替换 / 回滚都会被链式校验拒绝。
· headerMAC 覆盖全部头部字段，解密时先验后解，防止 KDF 参数被篡改后触发无意义解密。
· 每块 AAD 绑定 magic / version / kdfId / kdfParams / salt / baseIV / fileId / 时间戳 / 总块数 / 块大小 / 块索引 / 是否末块 / 密文长度，外层 AES-GCM 再绑一次 chunkIV。
· 明文在加密前填充至 1MiB 整数倍，隐藏真实文件长度。
· 密钥文件使用 AES-256-GCM + 独立 Argon2id（256MiB, t=10, p=1）保护，文件内不含明文密钥，A/B 通过 pairId 配对。
· 文件名解密后做消毒，防止路径遍历。单文件硬上限 256MiB。
· 纯 JS 无法保证恒定时间，也无法防御浏览器 0day、扩展、供应链、内存转储、键盘记录；JS 字符串不可变，密码无法真零化。高价值场景请配合 TEE / HSM / 硬件密钥。
