# Helix-Cipher

一个运行在浏览器里的多层文件加密工具。单个 HTML 文件，无需安装、无需后端、所有运算在本地完成。

---

## ⚠️ 定位与适用边界（请先读这里）

**本工具定位于「极端 / 应急情况下的自用备份方案」，不是经过认证的商用加密产品。**

- **已有的可靠下限**：外层 AES-256-GCM（NIST 标准，量子下约 2^128 仍安全）、ChaCha20（RFC 7539）、格层（LWE，实测 2^273.9，抗量子）。这三层的强度对所有人都一样，不依赖任何自研设计。
- **未经第三方审计的部分**：自研层（Feistel + Lai-Massey + Sponge）、Helix，以及全部周边逻辑（KDF 参数、链式认证、填充、头部解析）。统计测试合格，但无人做过密码分析。
- **不是认证级 FIPS 140-3 L3**：该认证需把硬件模块送进实验室测评；且 FIPS 140-3 明确规定纯软件模块认证上限为 Level 2。名称中的「L3-Hard+」是对标映射，**不是认证结果**。
- **重要数据请优先使用成熟方案**（VeraCrypt、硬件加密盘、经认证的密码管理器）。本工具适合作为极端情况下的额外一层备份，而不是唯一依靠。
- **忘记密码 / 丢失密钥文件 = 数据永久无法恢复**，这是设计如此，不存在找回途径。

---

## 架构

默认五层，勾选离散对数层后为六层。每层基于不同的数学结构：

| 层 | 结构族 | 依据 |
|---|---|---|
| 格层 | LWE | 格困难问题，量子下无已知多项式算法（NIST MLWE/Kyber 同族） |
| 自研层 | Feistel + Lai-Massey + Sponge | 轮函数分别为双哈希并联、Davies-Meyer、Keccak-f[1600] 原生置换 |
| Helix | SPN | 32 字节块，非 AES 域上的仿射逆 S 盒 |
| ChaCha20 | ARX | RFC 7539 |
| AES-256-GCM | SPN | NIST 标准，最外层，承担机密性下限 |
| （可选）离散对数层 | DL | RFC 3526 2048 位安全素数；**不抗量子**，默认关闭 |

设计目标是**结构多样性**：任一层被攻破，其余层不因共享数学基础而连带失效。

## 格层强度实测

使用官方 lattice-estimator 对实际参数（n=1344, q=65537, σ=1.0，秘密向量均匀分布）独立估算：

| 攻击模型 | 经典成本 |
|---|---|
| **primal_usvp（最脆弱）** | **2^273.9** |
| primal_bdd | 2^347.1 |
| dual | 2^989.1 |
| 量子筛（ADPS16 quantum） | 2^229.8 |

同环境校准：Kyber512=2^143.8，Kyber1024=2^275.1，Frodo1344=2^291.5，AES-256=2^256。

> 说明：估算在非 Sage 环境下借助兼容层运行，primal_hybrid / dual_hybrid 两项未跑通。这两项只会给出比 usvp 更高的成本，不影响结论。

## 密钥派生

Argon2id (1GiB, t=12) 与 PBKDF2-SHA512 (210k) 串联，后接 HKDF-SHA512。各层密钥使用独立 info 派生，互不复用，中间材料即时清零。

## 已知局限

- 自研层与 Helix **未经第三方密码分析**。统计测试合格，但统计合格 ≠ 抗密码分析。
- 纯浏览器实现，无法对抗：已沦陷的操作系统、浏览器 0day、键盘记录、物理内存取证。
- 非常慢。1MB 文件约需数分钟，手机上大文件有超时风险。
- 格式版本不向后兼容，升级后旧文件需用旧版解密再重新加密。

## 使用方法

1. 下载 helix-cipher.html
2. 按页面提示填入 Argon2 库源码（页面会校验其 SHA-512）
3. 用浏览器打开，确认三条自检全绿
4. 先拿小文件试跑闭环

> WebAuthn 凭据绑定域名。若使用硬件密钥因子，请始终使用同一域名打开。

## 开源目的

本项目公开的主要动机是**寻求密码分析**。自研层与 Helix 的设计意图已在上文说明，但其实际强度目前只有统计测试支撑。欢迎提交 issue、pull request 或任何形式的分析意见。
